# 网站客服回复扩充：使用与修改

本次准备 95 组通用回复、18 类待补商品资料。它们属于知识库与接待流程，不是重新训练 DeepSeek 模型权重。通用回复仅说明已知业务范围、核对流程和基础排查，不包含虚构价格、交付时间或授权。

## 在哪里检查

打开本地工作台 `http://127.0.0.1:3080`，左侧选择 **网站客服** → **01 知识与训练** → 下方 **知识清单**。

- `网站客服－…` 是本次通用知识，按开场、用途、选购、价格、购买、故障、售后等分类。
- `待补资料－…` 是 18 个模板，处于待审核，不参与回答。答案里有填写要求，必须换成真实资料后再审核，不能直接发布模板。
- 原来 4 条网站知识与服装演示空间保留。
- Ctrl+F 可搜索关键词，如“退款”“视频”“价格”“待补资料”。

只想快速看文案，可打开同目录 **网站客服-回复清单.md**。实际客服使用的是工作台数据库里的发布版本；仅修改 Markdown 或 JSON 文件不会自动生效。

## 如何改一条回复

1. 找到旧条目，点击 **以此修正**，内容会填入上方表单。
2. 修改上方的商品、标准问题、标准答案和真实资料来源。
3. 点击 **保存为待审核**。成功后直接替换原条目的内容并重置为待审核，不新增重复条目，无需手动撤回或删除旧内容。清空或保存失败不修改原条目；已发布快照继续保留。
4. 对修正后的条目点 **审核通过**。
5. 在 **02 问答实验室** 选择“草稿”，用客户的不同说法测试，包括不完整问题和连续追问。
6. 到 **03 版本与部署**，点击 **发布当前已审核知识**，核对变更后确认。再用实验室“发布”模式检查。扩展下一次请求会读取新版本，无需重新填写连接令牌。

修改客服语气或整体接待方式：在知识页右侧改 **客服规则** → **保存规则**，测试后同样发布。

## 建议优先补哪些资料

1. 实际在售商品及各规格价格、期限和额度。
2. 交付内容、账号归属、交付时效和所需资料。
3. 真实售后入口、工作时间，以及每种商品的退款条件。
4. 工具实际使用教程、适用设备与地区。
5. 经核实的网站入口和渠道设置。不能仅靠知识包自动开启发送网址。

每个实际商品建议单独写明确问答，不用“某商品”“以页面为准”代替你已经掌握的真实答案。资料来源写实际商品说明、经营者确认记录或官方文档及核对日期。

## 自动回复与人工的边界

普通选购、用途咨询、购买前政策咨询和基础排查尽量先给指引。实际退款、投诉、赔偿、扣款异常、交付争议，以及坚持索要资料中不存在的确切事实，仍应人工核实。不能通过增加话术来编造真实订单状态。

本次修正短问题/同义问法检索、购买前退款规则误判，以及“不要发送密码”这类提醒被误拦截的问题。真正索取敏感凭证、无依据报价、平台限制与发送结果不明的防护保留。新版本不会自动清掉之前的人工待办；处理旧待办后再恢复对应客户。

## 文件与备份

- `网站客服-通用接待.json`：95 组通用知识和客服规则，可导入其他业务空间；普通页面导入后均需重新审核。
- `网站客服-商品资料待补.json`：18 类资料模板，不含已确认商品参数。
- `网站客服-回复清单.md`：方便阅读的通用文案。
- `data/backups/pre-site-knowledge-时间戳.sqlite`：安装前完整数据库备份。
- `data/backups/site-knowledge-时间戳.json`：安装记录，包含新增条目 ID 和上一生效版本。
- `work/site-knowledge/model-check.json`：虚构咨询的实际模型验证结果，不向真实平台发送消息。

需要撤回本次正式回复时，可在 **03 版本与部署** 选择本次更新前的历史版本。这个操作切换生效快照，不删除知识草稿或人工待办。

开发用的 `scripts/build-site-knowledge.mjs` 会重新生成文案文件；不要用它保存日常人工修订。安装脚本默认只预览，明确传 `--apply` 才导入，重复运行不覆盖已有同名问答。
