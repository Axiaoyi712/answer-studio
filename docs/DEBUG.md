# 本地调试与平台限制处理

2026-10-23：服务 0.14.0 / 扩展 0.11.0 增加通用网页接待和独立渠道规则。请先查看[升级与网页演示验收](WEB-CHANNELS.md)。下面的平台故障处理仍适用，但不限制其他网页接入。

2026-10-22：服务仍为 0.13.4，扩展更新至 0.10.2。本轮增加工作台本地调试入口，并修复平台限制提示被路由切换错误覆盖的情况。没有增加绕过限制或伪装浏览器的功能，不能据此认为平台访问限制已解除。

## 现在先调试问答

1. 小红书网页再次显示“限制访问／浏览器异常”时，保持知答扩展停用，按平台提示处理。暂不反复启动网页接待。
2. 打开 [本地问答调试](http://127.0.0.1:3080/#debug)。打不开时先从项目目录运行 `start.cmd`；已有服务时不重复启动。扩展关闭也可以使用此页面。
3. 左侧选择要使用的业务，例如“网站客服”。在问答实验室选择“发布：当前生效快照”，点击“新会话”。此模式检查当前自动接待使用的知识；草稿模式检查当前已审核但可能尚未发布的内容。
4. 每次输入一个问题，检查回答内容、处理方式与下方引用。打开页面不会自动提问；主动发送测试问题会调用已配置的模型并产生相应用量。

| 测试问题 | 检查什么 |
| --- | --- |
| 你好 → 谢谢 → 你好 | 自然接话，不因三次问候触发追问上限 |
| 某项实际服务多少钱？ | 价格、计价单位和条件与真实资料一致 |
| 把上一题换成口语问法 | 能找到同一份相关依据 |
| 接着问“那这个多久交付？” | 沿用正确商品；没有交付依据时不能编时间 |
| 一次询问价格和一个缺失信息 | 有依据部分回答，缺失部分保留等待处理 |
| 一个明确但没有资料的商品事实问题 | 不乱编；处理不了时等待核实 |
| 要求保证永远不出问题 | 不生成无依据的保证 |
| 要求查订单、实际退款或转人工 | 识别为需要业务或人工处理，不声称已操作完成 |

实验室展示回复及处理建议，不会发送平台消息，也不代表真实客户待办已经创建或解决。网页收发、消息防重和人工窗口交接需要在接入方式确认可用后另外验收。

## 回答不正确时

- 引用不相关：检查商品名、别名、标准问法和答案是否清楚，补充与当前问题直接相关的知识。
- 引用正确但事实不符：保留问题、回答和引用，修正错误知识；若资料正确而回答被改错，需要检查事实核对或提示词。
- 草稿正确、发布模式错误：检查是否已经审核、发布，以及知识是否失效或被停用。
- 保存为待审核后：审核、发布，再回到新会话复测原题。测试通过的真实问题可加入“版本与部署 → 发布前回归检查”。

提交问题时可提供“顾客问题、实际回复、期望回复、引用资料、处理原因”。不需要提供模型密钥、本地连接令牌、账号密码或完整客户身份。

## 扩展 0.10.2 的修正

页面已显示限制时，启动前和读取结果返回后都会优先处理限制，不继续读取消息、不调用模型、不发送，并清除当前业务的自动恢复意图。首次尚未识别账号时也会停住，避免路由错误先返回而显示“会话已切换”。

重新加载扩展后需要刷新聊天页，旧页面不会自动换成新代码。本轮无需重启模型服务、重新训练知识或重新发布版本。账号目前若因启用接待反复受限，保持扩展停用即可，本地调试不依赖它。
