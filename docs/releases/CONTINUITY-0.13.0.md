# 统一资料与持续接待 · 0.13.0

服务 0.13.0，扩展 0.10.0。更新后工作台 Ctrl + F5；在 `edge://extensions` 重新加载扩展，再刷新聊天页。现有普通问答、业务与已发布快照继续保留，不必逐条迁移。

## 统一商品资料与引用

在“01 知识与训练”的知识清单上方展开“统一商品资料（可选）”。填写商品、常见问法和来源，按需要提供别名、单价及计价单位、规格、服务政策的支持状态、范围、条件和例外。价格按人民币单一计价单位记录；阶梯价、活动价等复杂规则继续用普通问答。

保存后成为待审核知识。对话建库也可根据经营者原话生成这些字段，仍需核对审核；不会把未知信息补成事实，也不会自动发布。

已有普通问答点击“引用统一商品资料”，选择本业务的资料卡。问法保留，答案、来源和字段随统一资料生成。关联操作使该问答重新待审核。解除关联恢复原问答文字，同样需要审核发布。

修改统一资料时，在其知识卡片点“以此修正”，进入字段编辑。核实并审核原资料，发布后相关引用问答统一更新；不必重复修改每个价格。原资料未审核时禁止发布依赖它的已审核问答，避免误撤回或外发未审核字段。停用或失效的原资料，其引用问答也停止生效。历史快照保留当时的数据，不跟随草稿改动。

导出知识包包含字段和关联，导入时重新建立当前业务的引用标识，导入内容全部待审核。被引用的原资料不能直接删除，须先解除引用。

## 意图、记忆和事实检查

- “不是投诉，我想了解规格”“不用转人工，我想问商品”可继续商品咨询；真实投诉和明确人工要求仍交待办。
- “想要P01，P01不一定可以”取消确定选择。已有颜色与型号改口保护保留。
- “开不了发票”等口语否定纳入政策检查；跨句、跨行的独立例外不会仅因句号丢失。
- 同商品不同问法的明确单价矛盾也会提示并阻止发布。活动、阶梯等条件价格不作简单单价比较；复杂语义仍需人工核对和测试集验证。
- 对外等待话术保持“不好意思，请稍等”，后台继续保留具体原因。

## 消息覆盖与轮转

开启日常接待后，面板显示当前列表的扫描范围。能唯一识别滚动容器时，默认每15秒最多推进一段，触发页面原有的列表加载，再读取已加载会话。每批最多40步后短暂停歇；检查到当前页面底部后回到顶部，稍后复查。陌生人列表单独记录范围。

这是页面可观察范围的分批检查，不代表平台全部历史会话或服务端未读总数。无法唯一识别滚动容器时保留已加载范围提示，不盲目滚动页面其他区域。平台限制仍会停发，不进行绕过。

当前客户完成或尝试一轮处理后，轮到其他等待客户；已读但已经进入任务队列的消息也参与。队列优先检查等待更久的可见客户。草稿、人工接管和发送结果不明确的客户继续单独隔离。

## 处理轨迹与同步

在“04 接待记录与归档”点“查看处理轨迹”，可查看收到消息、生成、进入发送前检查、准备发送、确认回显或交人工的阶段。新事件只记录实际经过的阶段，旧记录不补造轨迹。

各阶段在服务端与接待状态同一事务保存；本地服务暂时不可用时，在扩展中分别暂存，恢复后按顺序同步。其他账号积压的记录不会挡住当前账号。页面回显继续只表示页面显示发送结果，不等同对方已读。

## 先归档再清理

- 已有规则：30天前已完成接待先写入并校验 `data/archives/`，再移除在线记录；本轮归档还包含相应事件。
- 新增规则：90天前的模型计量、闲置会话记忆和接待事件，先校验归档到数据库旁的 `maintenance-archives/`，再事务清理。未完成客户对应的记忆与事件保留。当前知识、建库对话和发布版本不按此规则删除。
- 扩展“近期接待”中可点“归档并清理90天前已完成的旧任务”。每次最多100条，发送到本地服务的 `browser-archives/`，核对 SHA256 回执且确认本地条目未变化后才清理。仅处理已完成任务和由保留的处理进度覆盖的旧发送确认记录；人工、未知发送、草稿、处理进度和未同步内容保留。
- 归档文件可能包含咨询文字，应随实际业务数据一起备份。这些磁盘归档与浏览器数据不包含在 SQLite 数据库备份内，也不会随数据库恢复倒退。归档文件不自动删除。

## 质量测试集

“03 版本与部署”的回归题增加期望处理方式和禁止内容。除了“必须出现什么”，可以检查“应当追问／等待人工”“不能说保证到账”等要求。结果分开显示资料未召回、处理方式不符或出现禁止内容等失败原因。

可以导入和导出脱敏 JSON 测试集，每个业务最多50道发布回归题，引用须属于本业务。格式示例：

```json
{"cases":[{"question":"你好","expectedAction":"clarify","expected":[],"forbidden":["智能助手"],"sources":[]}]}
```

测试目标由经营者核实，不使用模型自报的置信度当正确率。关键词、引用和规则检查仍不能证明任意中文语义全部正确。真实正确率、漏回复率和转人工率还需用脱敏实际咨询与人工抽查评估。

## 服务守护

`start.cmd` 改为启动 `scripts/run-service.mjs`。服务进程异常退出后，守护进程按1至30秒退避重新启动；端口冲突或明确监听配置错误会停止并提示。关闭守护窗口、电脑关机或休眠不在持续运行范围内，未安装系统开机任务。

服务恢复不会取消浏览器里由你手动设置的暂停，也不会重试发送结果不明确的消息。浏览器、聊天页与登录仍需实际可用。

## 验收顺序

1. 用独立业务和测试账号，建立统一商品资料及一条引用问答。修改价格，验证审核发布前仍答旧价，发布后统一答新价。
2. 测试“不是投诉”“不用转人工”和同句型号改口；真实售后操作仍应交待办。
3. 让两位测试客户交替咨询，检查轮转；观察列表覆盖提示，确认新出现会话可被发现。不要把群聊未读计入私信漏答。
4. 查看处理轨迹，并用暂时不可用的隔离服务验证阶段恢复同步。生产客户的未知发送不用于自动重试测试。
5. 导入几道你已经核实答案的脱敏问题，设置必含、禁止内容和期望处理方式，检查发布前结果。

本次开发验收使用隔离数据库、模拟网页和真实模型合成资料，不向真实客户发送测试消息。结果与升级备份回执见 `work/continuity/`。

升级会新增字段表、引用表、事件表和测试检查字段。升级前的数据库已单独备份；旧结构备份的页面恢复会被阻止，须停服后离线恢复并由新版重新执行迁移。新版创建的同结构备份仍可在“06 备份与恢复”操作。
