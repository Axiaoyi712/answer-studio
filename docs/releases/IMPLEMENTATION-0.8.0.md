## 更新后使用

1. 重启本地服务，打开工作台确认服务版本 0.8.0。原知识、审核和发布版本继续保留。
2. 在 `edge://extensions` 重新加载 `edge-extension`。版本应为 0.8.0；接受新增的小红书站点访问、通知和定时提醒权限，刷新消息页面。
3. 首次连接填本地连接令牌，选已发布业务，点击“检查并开始接待”。连接令牌和业务选择保存在此浏览器本机，重启无需重填。它不是 DeepSeek 密钥。
4. 这一个标签页作为自动接待专用页。人工从待办打开独立窗口；关闭人工窗口自动恢复对应客户，其他客户继续接待。
5. 标题可拖动；“缩成悬浮球”会吸附侧边，点击展开。收起不会停止接待；待人工数量显示在球上。点击“停止全部自动回复”或关闭客服面板才停止当前工作；账号、页面或平台全局异常仍会停发。
6. 重新打开浏览器和聊天页：上次正在工作时，账号和本地服务检查通过后自动恢复；上次主动暂停则保持暂停。不自动打开浏览器，不会在电脑关机、休眠或浏览器未运行时工作。

## 选项落实

| 原选择 | 实现位置与行为 |
|---|---|
| 1 专用页＋独立人工窗口 | 自动任务绑定唯一标签页。专用页有草稿时保留原文、明确显示等待，人工应使用独立窗口。 |
| 2 关闭人工窗口即完成 | 绑定窗口关闭后定向交回对应客户；全局已暂停时只恢复客户状态，不擅自开始发送。 |
| 3 持久待回复任务 | 发现的未读会话先记入本机任务；之后即使被标为已读，仍继续寻找该任务。仅覆盖实际加载并发现的消息。 |
| 4 发送结果不明只隔离客户 | 保留 unknown 防重记录，转人工核对，不自动重发；其他客户继续。 |
| 5 简洁摘要＋详情 | 待办显示名称、问题、原因、等待时间，展开查看近期对话、拟回复和依据。 |
| 6 一键启动 | 自动检查服务和已发布业务，记住上次业务；0.8.1 已删除旧监听和弹窗手动草稿入口，验证功能统一在客服面板。 |
| 7 桌面通知＋角标 | 新待办通知一次，扩展角标与悬浮球显示数量，点击通知展开原客服待办。不在通知正文展示客户聊天。 |
| 8 重启自动恢复 | 本机持久保存工作意图和账号；恢复前检查登录账号及服务，保留任务和人工状态。 |
| 9 最多两轮追问 | 连续澄清两轮后再遇到不明确需求转人工；明确人工请求或缺乏事实依据可直接转人工。人工完成后重置计数。 |
| 10 人工答案成为知识 | 待办详情和近期接待支持 AI 提炼可编辑草稿；人工补充来源后保存为待审核，审核发布后才生效。工作台记录也有整理入口。 |
| 11 可拖动悬浮窗＋球 | 记住本机位置、展开状态；收起真正隐藏面板，不占据大块网页。 |
| 12 简洁状态＋故障提醒 | 显示运行/等待/连接异常、最后检查、待回复、待人工；全局异常提醒。 |
| 13 生成失败重试 | 外层请求最多重试两次，间隔 2、4 秒；生成前后仍校验会话和消息。模型内部原有格式修复仍保留，最多两次，共用 45 秒预算。发送不重试。 |
| 14 连发合并 | 停顿约 3 秒触发生成，持续发消息时约 10 秒触发本轮生成。生成中又有新消息会丢弃旧答案重新核对，避免旧答错发。 |
| 15 五分钟提醒一次 | 待办五分钟未开始处理，再提醒一次；打开独立人工窗口后不再催。 |
| 16 保留 30 天，先归档 | 已完成记录满 30 天后，写归档、刷新文件、SHA256 校验，再删除精确对应的在线行；失败保留原记录。未完成不清理。 |
| 17 本机按月归档 | 默认 `data/archives`，按记录更新时间月份归档；可在 `.env` 设置 `ARCHIVE_DIR=E:/你的目录` 后重启。工作台可查看和下载。 |
| 18 错答人工纠正 | 近期接待和待办详情中标记错误，客户转人工；正确答案可整理为待审核知识，不自动补发纠正话术。 |
| 19 发布提示与差异 | 持续提示未发布修改，确认发布前展示规则和知识变更。 |
| 20 非文字转人工 | 图片、语音、文件等有消息气泡且可确认归属时进入待办，说明类型；不猜测内容。 |
| 21 人工回复暂停该客户 | 人工窗口原本即隔离；主窗口检测到新增人工回复也移交该客户。人工窗口对话仅用于交接、知识整理。 |
| 22 24 小时历史边界 | 最近 24 小时咨询自动处理；更早或首次出现时无法确认时间的咨询列“历史待确认”，不补发。已建立同会话尾部基线后新追加的消息，可用实际观察到达时间。 |
| 23 一次等待说明 | 常规转人工发送一次“这个问题需要人工核实，请稍等。”，走同一发送前校验和回显路径；历史、不明确发送、输入草稿等情况不冒险补发。 |
| 24 明确询问才提供网站 | 默认不允许。工作台“版本与部署”填写审核网址、确认渠道允许；客户明确询问且答案引用的审核资料包含同一地址时才通过。其他网址、凭证索取仍拦截。配置不等于平台授权。 |

## 数据与边界

- SQLite 新增接待记录和渠道设置表，现有知识表不重建。工作台按业务查询、每页 100 条，归档可另行查看。
- 扩展本机保留待回复队列、人工状态、防重标识、近期详情和未同步记录。服务不可达时正文先留在本机待同步箱；成功同步后才移出待同步箱。已同步的已完成详情缓存最多保留最近 20 个客户、最长 30 天；更早记录仍可到工作台查询，服务端记录执行先归档后清理。未完成人工详情继续保留。
- 日志中的“确认发送”表示页面出现对应的新己方消息，不是平台服务端送达回执。unknown 必须人工核对。
- 归档包含聊天内容，存放在你指定的本机目录；此版不上传云端。
- 原“问答实验室”的测试会话历史仍属于测试数据，独立于新增的真实接待记录保留策略。
- 单机、单自动控制标签页；不扩展成多人客服或多账号 SaaS。
- 新增通知、定时提醒和自动恢复所用接口依据 [Chrome Notifications](https://developer.chrome.com/docs/extensions/reference/api/notifications)、[Alarms](https://developer.chrome.com/docs/extensions/reference/api/alarms)、[Content scripts](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)。不绕过平台限制。

## 分步验收的必要性

先验收任务和防重，再验收人工交接和通知，最后验证真实页面。原因是重复发送和发错客户属于外部可见结果，不能只凭一个最终截图证明可靠。开发阶段均使用隔离数据，没有向真实客户发消息。

自动化命令：

```powershell
npm.cmd test
node scripts/verify-inbox-browser.mjs
node scripts/verify-workbench-browser.mjs
```

前者覆盖服务、归档、网站规则、AI 草稿和扩展绑定；后两者分别在隔离 Edge 中验证接待流程和真实工作台页面。浏览器截图和结果存放在 `work/inbox-browser`、`work/workbench-browser`。

还需真实账号验收，无法由虚拟 DOM 替代：

1. 找配合测试的账号发一条咨询，再连续发两条，核对只回复正确客户、合并内容正确。
2. 发一条需人工的问题，确认实际桌面通知出现；五分钟不处理确认仅再提醒一次。
3. 打开人工窗口处理 A，同时让 B 咨询；确认 B 继续接待。关闭人工窗口后 A 再问新问题，确认恢复。
4. 缩成悬浮球，拖动、展开；切到其他应用，确认实际 Edge 后台未因休眠而冻结。
5. 运行状态刷新聊天页验证自动恢复；主动暂停后刷新验证保持暂停。无需测试真正关闭全部浏览器来冒险验证多个窗口关闭顺序。
6. 网站自动发送默认关闭；完成你账号的渠道规则核实后再勾选允许。没有核实不作为验收失败。

若平台出现限制访问，停止扩展，按平台提示处理；不以修改识别或伪装浏览器规避限制。
