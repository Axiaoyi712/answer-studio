# 回复可靠性与草稿隔离 · 0.12.0

服务 0.12.0，Edge 扩展 0.9.2。更新后工作台 Ctrl + F5；在 `edge://extensions` 重新加载扩展，再刷新聊天页。原有知识和发布版本无需重新导入。

## 本次改进

1. **业务政策核对**：覆盖开票、退货、换货、退款、保修、试用、定制、货到付款的常见肯定与否定表述。核对商品型号、电子/纸质发票、无理由退货等范围，以及付款后、未拆封、未使用、金额门槛、定制除外等已识别条件。真实引用不能为反向政策作依据，发布回归检查也使用这些校验。小知识库的政策短问法增加主题匹配，避免已有资料却没有召回。
2. **口语改口记忆**：“蓝色不行／不合适／不能接受／还是算了，黑色可以”会覆盖此前“蓝色可以”。“蓝色不一定可以”等含糊说法取消旧的确定偏好。型号的后置否定同样生效；长对话和重新读取仍延续最新记忆。
3. **冷却期间继续简单接待**：模型连续失败进入冷却时，纯问候、简单确认和致谢仍可由本地规则回复，不调用模型。混合商品问题继续交待办，不使用内部配置提示冒充答复；冷却不会因这些本地回复反复延长。明确人工请求、真实业务操作仍按原规则处理。
4. **草稿只影响当前客户**：自动接待页发现人工草稿，先按账号和会话保存到扩展本地存储，再跳过该客户，继续其他待回复私信。返回原会话时恢复草稿；重开助手后仍可恢复。页面已有新草稿时以页面内容为准，不拿旧备份覆盖。

## 草稿如何使用

- 面板的“已保留的草稿”显示客户、只读正文和复制按钮。备份仅保存在当前 Edge 配置的扩展本地存储，不发送给模型，也不随服务端数据库备份迁移。
- 在聊天列表打开对应客户，运行中的助手会检查并恢复草稿。**恢复不会自动发送草稿**。人工编辑仍建议使用独立窗口。
- 在原输入框清空草稿，助手识别后移除该会话的本地备份并恢复自动接待。人工发送会继续遵循原来的会话接管机制，可在人工待办恢复该客户；其他客户保持接待。
- 首次发现草稿需等待一次页面检查；界面显示“当前草稿已保留”后才表示备份完成。保存失败会报错并暂停，保留原输入框，防止切换导致丢稿；修复后点击开始接待会重新保存。
- 该客户不在列表可见范围时，备份仍保留；自行在页面找到并打开会话后恢复。卸载扩展或清除扩展数据会清除本地备份，请先复制重要草稿。

## 实际验收

先创建独立测试业务，用可配合的测试账号；不要把合成价格和政策写进正式业务。

1. 添加“付款后支持电子发票，不提供纸质发票”和“未拆封支持退货，定制除外”等实际确认的测试规则，审核并发布。询问开票、纸质发票、退货条件，应保留相应否定和条件。
2. 同一测试客户先说“蓝色可以”，再说“蓝色不行，黑色可以”。继续问需求时不得把蓝色当成仍接受。
3. 日常接待时，在客户 A 的原输入框留下草稿，等提示保存完成，再由 B 发来可回答问题。B 应正常收到回复；打开 A 时恢复原草稿且不自动发送。清空 A 草稿后，再向 A 发新问题，应继续自动接待。
4. 暂停、重新打开助手并启动，检查草稿仍可恢复。页面已有更新的手工文字时不得被旧备份覆盖。
5. 冷却场景已在隔离测试里模拟；纯“你好”“谢谢”可继续回复，带商品问题的消息仍交待办。生产环境不必主动制造模型故障。
