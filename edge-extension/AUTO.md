# 智能客服 v0.7.7 使用与验收

v0.7.7 取消普通人工操作和失焦暂停：鼠标点击、键盘输入、切换窗口或标签页不再停止日常接待。后台请求仍限定原绑定标签页和主框架，不扩大站点权限；旧草稿助手的前台限制不变。点击“停止全部自动回复”仍立即取消正在生成的答案并停止后续发送。以下历史版本中的前台和人工操作限制已由本版本替代。

原自动页面聊天输入框有草稿时，保持运行并等候，不覆盖草稿或切走会话；清空或发送后继续检查。模型生成时出现人工草稿，仅将该会话交人工，不中断整体任务。人工切换聊天时丢弃旧生成结果，重新核对正确客户；若切换发生在填写后，原草稿交人工核对，若已经尝试发送，保留 unknown 防重记录并移交该会话，其他会话继续。账号变化、平台限制、真实发送失败或无法识别页面等故障仍停发，不能把本版本理解为遇到任何故障也强制发送。

后台运行仍依赖 Edge 页面和本地服务实际在运行。本地模拟已验证失焦/隐藏状态下的流程，不能保证真实浏览器后台时效；关闭页面、关闭浏览器或电脑睡眠不属于持续接待。原页面需要人工回复时建议使用独立人工窗口，避免共享输入框的等候影响接待节奏。

v0.7.6 自动完成交接：从待办打开独立人工窗口，处理完成后直接关闭整个人工窗口，即视为确认人工已完成。扩展自动聚焦原客服窗口，并通知原控制台恢复对应客户，不用再找待办卡片点击。其他客户的接待任务保持运行；如果之前主动停止了全局接待，只恢复该客户状态，不自动启动发送。卡片恢复按钮保留作备用。

只有当前绑定创建的人工窗口关闭才触发交接；关闭无关窗口、旧连接的人工窗口或已不存在的原客服，不会触发恢复，也不会重建窗口。原控制台继续校验账号和防重记录；校验失败保留待办，在原面板查看失败原因后手动恢复。请处理完成后再关闭人工窗口；关闭整个浏览器不作为可靠交接方式。没有通过空闲时间或发送任意一条消息推断处理完成。

v0.7.5 在每位客户的人工待办卡片上新增“人工已完成，恢复自动接待”。处理完先关闭该客户的人工聊天窗口，再回到原客服面板点击此按钮。操作不导航原页面、不停止其他客户接待、不调用模型；移除该客户的人工待办并恢复接待资格。接待运行时会安排检查一次列表已加载的该客户会话，即使它已被标为已读；之后继续接待未读新消息。全局已停止时只更新客户状态，不自动启动发送。

转人工时额外保存原待办的消息 ID，不保存正文。恢复只跳过原待办，人工回复之后的新提问、接管期间后来到达且尚未回答的新问题仍可交给 AI。原 sending/unknown 防重记录保留；兼容旧版从对应发送记录恢复原待办 ID。恢复后请关闭该客户的人工聊天窗口，避免它持续把后续消息标为已读。新恢复按钮与旧“跳过当前全部消息”按钮语义不同，推荐使用卡片按钮。

v0.7.4 将待办入口改成“独立窗口人工处理”。扩展通过 [Chrome Windows API](https://developer.chrome.com/docs/extensions/reference/api/windows) 创建独立的普通浏览器窗口，只打开该会话，不导航原自动客服标签页，也不向人工窗口注入自动回复程序。同一待办重复点击会聚焦已有人工窗口；不同待办分别打开。自动客服继续在原标签页接待其他顾客，人工会话仍保留接管状态。扩展仅在原自动窗口或由该连接打开的人工窗口获得焦点时继续工作；原标签页隐藏、切换标签页、原页面人工操作、账号变化或平台限制仍暂停。窗口关闭后可重新打开。无需增加权限，后端无需重启。

建议将原自动客服窗口和人工窗口并排放置；不要最小化原窗口或让其标签页隐藏。人工窗口直接使用同一浏览器的登录状态，首次使用需实机确认平台是否支持两个窗口同时接待；本地模拟不能证明平台多窗口会话始终有效。

v0.7.3 将人工接管限定到对应会话：日常接待运行中点击“仅接管当前会话”，会取消该会话正在生成的答案并保留人工状态，随后继续接待其他顾客，无需再次启动。问答服务请求失败也只将当前会话加入人工待办，不自动重试，其他会话继续。红色提醒同步显示其他顾客是否仍在自动接待。“停止全部自动回复”仍会停止整个接待流程；发送结果不明确、平台限制、账号或页面变化等情况仍会全局暂停。后端 0.7.1 仍兼容，无需重启。

v0.7.2 仅更新扩展提醒：顶部固定红色人工待办条显示数量、最近的会话和原因；新增或原因变化时展开人工列表并滚动到处理入口，只滚动控制台，不改变底下聊天页面。每条待办独立卡片展示会话名、原因和“立即处理该会话”。扩展图标显示当前聊天标签页的待办数量，队列清空后清除。重复检查不会反复展开已收起的同一待办。无需增加浏览器权限，后端 0.7.1 仍兼容，无需重启服务。

v0.7.1 修复模型格式错误：短客服问答明确关闭思考模式；兼容完整 JSON 代码块；区分空内容、截断、字段错误和生成中断。空内容、截断及格式问题最多重新生成一次，两次请求共用 45 秒预算，不是重试发送。连续失败转人工；过滤、中断、HTTP错误、无有效资料引用不会通过格式重试绕过。诊断只保留类型、结束原因、内容长度和请求次数，不包含原始内容或思考文本。参数依据 [DeepSeek Chat Completions 文档](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/)；文档说明默认思考模式启用，且长度限制可能截断 JSON。

本地服务负责知识问答，Edge 扩展负责读取、打开会话和发送。已完成连续接待、人工接管、恢复、防重和分阶段测试；这不是平台官方客服接口。用户实机已验证读取和草稿，真实发送与平台兼容性仍需验证。

## 更新和启动

1. 本地服务运行后，打开 http://127.0.0.1:3080 。扩展弹窗显示服务 0.7.1 与 DeepSeek 已配置；若提示旧服务，关闭原服务窗口再运行 start.cmd。
2. 在 edge://extensions 重新加载项目的 edge-extension 文件夹。扩展版本应为 0.7.7；刷新小红书消息页。
3. 扩展首次连接填写 data/edge-bridge-token.txt 中的本地令牌。不是 DeepSeek 密钥。令牌仅存在浏览器会话中，重启浏览器需重填。
4. 选择已发布的业务，点击“打开智能客服”。扩展会记住上次选择的业务，不需要填写顾客信息或 CSS。
5. 首次进入仍默认只检测。确认测试会话中能正常生成草稿，再选择自动回复模式验证一条发送。

## 日常接待

点击“开始日常接待（自动发送）”会开启连续回复及未读会话切换，处理：

- 当前会话中最后一次己方回复之后、尚未处理的消息。
- 列表中已加载的未读单聊，包含陌生人消息夹。
- 页面新增文字、多条合并提问及结合真实历史的追问。

群聊不自动回复，图片和语音等非文字消息交人工。不能凭空回答未录入的商品价格、库存、交付或售后条件。需要在工作台整理知识，审核、测试并发布。

开启日常接待后可以操作其他窗口或切换标签页，无需因普通人工操作再次启动。人工待办仍可通过面板打开独立人工窗口。共享聊天输入框有草稿时等候，清空或发送后继续；需主动停止请点“停止全部自动回复”。刷新、关闭、平台限制、账号变化及真实发送异常仍会停发；刷新后不自动开始发送。

## 人工接管与恢复

- 超纲、明确人工事项或审核未通过的回复，会进入“需要人工处理”。当前会话暂停自动回复，其他会话继续。
- “仅接管当前会话”保存当前会话的人工状态。运行中使用时取消该会话当前任务，其他顾客继续自动接待；停止状态使用时不会擅自启动。
- 人工列表点击“独立窗口人工处理”，在新窗口直接回复该客户，原自动页面保持原有任务。不要在人工窗口再开启自动客服；该会话的人工状态会保留。在原自动页面手动切换聊天也不会停止整体任务，但输入框有草稿时会等候。
- 推荐：人工处理完成后关闭该客户的整个独立聊天窗口，自动回到原客服窗口并恢复该客户接待。无需找卡片或切换客户；新问题继续由 AI 回复，原待办不补发。
- 备用：若自动交接失败，可在原面板对应卡片点击“人工已完成，恢复自动接待”。
- 保留旧控制：“已人工核对，跳过当前消息并恢复”用于明确要跳过当前会话全部待处理消息的情况；它会停止整体接待，需再次开始。
- 发送结果不明确时，原来的 sending/unknown 记录不会被删除；人工恢复也不自动补发这批文字。
- 人工队列属于本机扩展，没有外部客服派单或通知服务，不会向顾客宣称已联系其他人。

会话状态按登录账号和会话 ID 隔离，所有业务共用平台发送防重，避免换业务后对相同消息重复发送。保存账号/会话/消息标识、会话显示名称、状态原因和时间，不保存聊天正文。跳过标识最多保留最近 1000 条。卸载扩展会丢失本机状态，不应在发送结果不明确时用卸载解决问题。

## 保留的分阶段模式

| 模式 | 模型问答请求 | 填写 / 发送 | 默认范围 |
| --- | --- | --- | --- |
| 只检测 | 无 | 无 | 当前页 |
| 生成回复 | 有，简单接待也可能由本地规则处理 | 无 | 当前会话 |
| 自动回复 / 单条验证 | 有 | 成功一条后停止 | 当前会话 |
| 日常接待按钮 | 有 | 连续回复 | 当前及其他未读单聊 |

会话切换和连续回复也可分别选择。打开未读会话可能将消息标为已读。草稿仅在本次面板内记住已读到的消息，继续生成时只处理新一批文字；未发送草稿不会冒充己方历史或写入发送记录。切换模式会停止任务并丢弃迟到答案。

## 回答与知识维护

“本次合并的问题”显示实际提交的问题；最近真实消息作为上下文。回复显示 DeepSeek/本地规则来源和判断原因。没有检索结果时，配置好的模型仍可接待、澄清需求，但没有有效资料引用的商品事实回答会被拒绝。

训练流程：在工作台选业务 → 添加 product、question、answer、source → 核对后审核 → 在问答实验室测试 → 发布。换衣服或文具等业务时新建独立空间并选择对应发布版本。知识包可以导入导出，不需要重新训练模型权重。

本站目前只有少量已审核知识，无法覆盖网站所有商品。商品负责人需要持续补齐服务范围、适用条件、价格依据、交付方式和售后规则。不要把未知事实写成承诺，也不能把资料引用存在当作回答必然准确。

## 诊断与运行状态

面板展示生成次数、确认发送次数、人工队列及阶段日志。“生成诊断报告”只导出阶段、操作计数和最后失败阶段，不含正文、顾客标识或连接令牌，也不会额外读取网页。

网页有变化时进行检查，空闲时每 5 秒补查一次；不会每秒完整读取未变页面。陌生人文件夹如果只剩人工会话，最多每 30 秒复查，未读数或最新消息时间变化时会重新检查。以上间隔是本项目的工作节奏，不是平台安全配额。

发送前保存 sending，检查账号/会话/消息序列/输入框，再通过网页 Enter 发送。新增己方消息无发送中和失败标记、输入框清空后保存 echo-confirmed。它是网页回显，不能代替平台独立送达回执；不明确时停发，禁止自动重试。

## 实机验收顺序

1. 测试会话只检测：没有限制提示，双方消息归属和当前会话正确。
2. 草稿：分别测试问候、真实产品问题、追问、缺资料问题。
3. 单条发送：确认只向正确会话发一条，面板显示单条验证完成，不重复。
4. 日常接待：两个可配合测试的会话分别来信，均被回复；自己的消息不触发循环。
5. 人工：一个问题超纲，另一个会话继续；核对恢复后旧消息不重发，新消息可回复。
6. 操作与暂停：鼠标键盘、切窗口及切标签页保持接待运行；手工草稿不被覆盖，清空后能继续。点击停止后新消息不再发送；刷新或真正的发送异常仍停发。

如果再出现小红书“限制访问 / 浏览器异常”，应停用扩展并按平台提示处理，不反复启动或尝试绕过。此前停用扩展后限制消失，不能据此证明今后不会触发。
