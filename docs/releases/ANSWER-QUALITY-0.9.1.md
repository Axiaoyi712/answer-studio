# 回答质量第一批改进 · 服务 0.9.1 / 扩展 0.8.11

本次落实架构分析中的第一批：检索、型号约束、关键事实核对和人工原因分类。保留现有业务、知识、审核状态与发布版本。

## 具体变化

1. 商品名、标准问题及答案正文参与加权检索，保留标准问题多个问法的精确优先匹配。增加常用表达归一，例如打印纸/复印纸、一沓/每包、邮费/运费、笔头/笔尖。商品别名可以继续写在商品名、标准问题或答案中。
2. 明确出现 P01、P02、A3、A4 等型号时，排除不匹配型号的专属知识；当前换型号时不从上一型号的问题补回证据。通用规则仍可检索。
3. 模型回复在返回前核对常见显式数值、单位、计价单位、颜色、型号及部分承诺。包括起步价、发货/送达区别、预售例外、普通天数/工作日区别。合理的单位换算、中文数字和必要追问可通过。
4. 标记为“澄清”的回复同样接受事实核对，不能夹带无依据的价格。未通过时只向客户回复“不好意思，请稍等”，具体原因保留在后台。
5. 人工待办区分缺少知识、回答需核对、模型格式异常、问答服务故障、发送待核对、页面/连接故障、历史消息、非文字、售后/业务处理、客户要求人工、需求不明确和人工接管等类别。
6. 工作台“接待记录与归档”显示类别，可筛选当前页记录；扩展待办卡片也显示类别。旧记录读取时按已有原因分类，不批量改写历史。
7. 对话建库只向你追问真正缺少知识的记录，服务、发送、页面和售后处理不作为知识缺口。接管、完成人工处理时保留同一任务的原始分类。
8. “别发密码”“不要在聊天里发密码”等完整否定提醒不再误拦；实际索取和混杂索取仍拦截。

## 更新与使用

本地服务更新到 0.9.1 后，保存未提交的编辑，刷新工作台。到 `edge://extensions` 重新加载扩展 0.8.11，再刷新小红书聊天页面。已有审核发布知识继续使用，无须重新导入或发布。

本次没有给真实业务添加文具价格、规格等测试资料。需要试验文具例子时，新建测试业务并自行填写确认的资料，不要把测试价格加入正式客服。

## 实际验收

- 答案正文写有打印机适用情况，标准问题只写“规格”：在问答实验室换个问法询问适用情况，应能找到对应资料。
- 两款商品型号、价格不同：分别提问应匹配各自资料；再问不存在的型号，应追问或等待，不套用上一款。
- 发货规则包含“预售除外”：正常回复应保留这个条件，不将发货时间说成到货时间。
- 查看真实人工记录：核对分类是否贴切；“补齐接待难题”只提取知识不足的记录。

## 验证与边界

验收使用隔离数据库、合成商品和虚构咨询，不发送真实客户消息。自动回归和浏览器检查结果在 `work/inbox-browser/`、`work/workbench-browser/`；真实模型文具检查在 `work/answer-quality/`，通用接待检查在 `work/site-knowledge/model-check.json`。

事实核对是常见字段和条件的确定性检查，不是完整语义证明；新的单位表达、复杂条件、同一资料中多个商品及隐含关系仍可能需要人工检查。此次未增加向量检索、重排模型、完整订单接口、知识有效期或多渠道接入，不应把本次测试结果理解为真实业务准确率或长期可用性承诺。
