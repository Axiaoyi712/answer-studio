# 对话建库 · 0.10.0

在本地工作台的“知识与训练”里使用，现有手动表单保留。使用你已配置的 DeepSeek API，密钥留在服务端。

1. 新建业务空间，例如“文具客服”，或选择已有业务。
2. 在顶部“对话建库”中点“开始了解业务”，或直接输入“我做文具客服，主营中性笔和打印纸”。
3. 按它的问题说明实际商品、规格、价格、适用条件、发货和售后等。每轮通常追问 1–3 个问题，不清楚的可以直接说暂不提供。
4. 已确认信息自动拆成待审核问答，来源记录你的原话。右侧展示本轮整理结果，随时可以点“总结并入库”汇总。
5. 点“查看待审核知识”，核对或“以此修正”，再审核、发布。发布后才供正式客服调用；待审核知识不会自动对外使用。

有人工接待记录时，点“补齐接待难题”。系统从当前业务在线人工接待记录（待人工、人工处理中、已完成）提取知识不足的问题并持久保存，每轮向模型提供最多 20 条可追问缺口。已存成草稿的缺口继续显示待审核、待发布、待验证，不重复索取同一答案；用原问题验证通过才关闭。服务、发送及页面故障不作为知识缺口。详见 [知识闭环与运营验收](releases/BUSINESS-QUALITY-0.10.0.md)。客户问题只用于发现缺口，需要你确认答案后才形成待审核知识，不会改变客户的人工待办或自动发送消息。已关联知识被删除后，对应缺口会重新出现。

每个业务分别保存建库对话。刷新、重启或切换业务后可以继续；发给模型的是最近 30 条建库消息和最多 300 条现有知识摘要，完整对话仍保存在本地数据库。建库对话与“问答实验室”的顾客测试会话独立。

“建库主题进度”长期保存类目、规格、价格、购买、发货、售后与例外七类主题，状态包括尚未询问、部分提供、已提供资料、暂不清楚、暂不提供、不适用。模型更新必须引用经营者原话；也可以在进度中手动修改。未知和暂不提供不作为确定商品答案。

相同商品与标准问题会去重：答案未变则保留；待审核答案变化则更新原待审条目；与已审核答案冲突时另存为待审核并提醒，原审核知识和发布快照保留。确认修正后请撤回旧答案再发布，避免并存冲突。不同问法可能仍需人工合并，原话引用校验不能代替内容审核。

模型失败不保存半条知识，原输入在当前页面保留，可直接重试；重复提交同一请求不会重复调用模型或入库。不要在建库对话里填写密码、验证码或客户个人订单信息。

## 验收

- `npm.cmd test`：包含对话持久化、业务隔离、来源校验、去重、冲突保护、失败回滚和并发检查。
- `node scripts/verify-workbench-browser.mjs`：隔离数据库与模拟模型的真实 Edge 浏览器检查，不向真实客户发消息；结果与截图在 `work/workbench-browser/`。
- `node --env-file-if-exists=.env scripts/verify-interview-model.mjs`：使用已配置 API 的文具场景联调，测试数据独立存入 `work/interview-model/`，会产生模型调用费用，不写现有业务。
