# 0.13.2：自然收尾与售后咨询分流

本次针对公开数据中保留的真实失败及合成商家测试改进客服核心。服务版本 0.13.2，扩展仍为 0.10.0；不修改正式商品知识、审核结果或已发布版本。

## 改了什么

| 客户消息或资料 | 本次行为 |
| --- | --- |
| “好的，我的问题你都解答完了，谢谢你了。” | 本地简短收尾，不请求模型、不额外转人工；模型冷却时也能正常致谢。 |
| “OK, 我知道了, 谢谢啊!” | 支持英文逗号和常见分号，不再因标点漏掉普通接待。 |
| “谢谢，P01多粗，一支多少钱？” | 感谢不能吞掉后面的商品问题，继续检索并核对依据。 |
| “退款一般几天到账？” | 进入规则咨询，使用该业务已审核资料；缺少政策仍不能猜测。 |
| “我的退款一般几天到账？” | 保留为个人业务待办，不根据一般政策猜测真实订单进度。 |
| “帮我换货”“帮我取消订单”“我要修改收货地址” | 保留业务待办，对外只发“不好意思，请稍等”，不宣称操作完成。 |
| “不想退款，我只是问P01的价格” | 不因被否定的办理意图挡住正常咨询。 |
| “支持退货和换货” | 核对器识别并列共享的肯定或否定；客户单独问换货也能使用这条依据。未拆封等条件和定制例外继续核对。 |

模型提示词明确区分普通致谢收尾、规则咨询和实际办理。对已经结束咨询的客户简短结束，不再反复问“还需要什么帮助”。没有引用的事实回答仍会被阻止，不把模型误分类直接改成可发送回复。

## 如何实际检查

1. 刷新本地工作台，确认服务版本为 0.13.2。已连接的 Edge 扩展无需重装；新生成的回复使用新逻辑。
2. 在“问答实验室”选自己的业务及发布版本，测试“好的，我的问题你都解答完了，谢谢你了”。应直接收尾，不生成知识缺口。
3. 对有真实退款资料的业务，分别测试“退款一般几天到账？”和“我的退款一般几天到账？”。前者按资料回答，后者保留业务待办。
4. 测试“谢谢，某商品多少钱？”。应根据商品依据答价；不能只回答“不客气”。
5. 在可配合测试的聊天会话里再验证实际页面接待。本次自动验证没有向小红书或真实客户发送消息。

如果没有真实退款、退换货条件或时限，先到对应业务的“知识与训练”或“对话建库”补充真实资料、审核并发布。本次合成测试里的价格、时限和售后规则不会进入你的业务。

## 仍有边界

分流仍包含规则判断，不能完全理解所有否定、多段消息和复杂售后描述；一般规则也不能证明某个订单符合退款条件。关键事实核对不是通用语义证明。新增测试是已知回归与合成场景，不等于线上正确解决率、独立泛化准确率或模型置信概率。

本次没有扩大百科服务范围、放松事实引用门槛，或把旅游/银行等公开数据的价格承诺写入正式知识库。真实店铺出现的新漏答，仍应脱敏后加入该业务回归题，并核对其真实依据。
