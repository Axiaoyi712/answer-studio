# 持续接待与回答核对：服务 0.13.4 / 扩展 0.10.1

本轮修复自查已复现的漏单、普通接话误转人工和事实核对缺口，不修改正式商品资料、审核状态或已发布版本。不需要重新建库。

## 更新与使用

1. 本地服务使用 0.13.4。浏览器打开 `http://127.0.0.1:3080/api/status` 可查看版本；后台服务已运行时，不重复启动多个实例。
2. Edge 打开 `edge://extensions`，找到“知答 · 小红书智能客服”，点击重新加载。
3. 刷新专用聊天标签页，再打开客服面板。面板显示 0.10.1 后，点击“开始日常接待”。旧面板不要继续操作，避免扩展上下文失效。
4. 人工处理继续使用独立窗口。更新保留原有待办、草稿与处理进度；已存在的人工待办不会擅自恢复。

## 本轮行为

| 场景 | 处理 |
| --- | --- |
| 客户问题后面有失败或仍发送中的己方气泡 | 进入“发送待核对”，保留问题，不记为已完成，不重新调用模型或自动重发；其他客户继续接待 |
| 发送气泡从等待变成失败等状态 | 页面快照变化，旧快照不能用于发送 |
| 核对旧回复后恢复该客户 | 跳过原人工待办，新问题继续；需要补答旧问题时在人工窗口处理 |
| 连续问候、致谢、告别、普通接话 | 不累计澄清次数，不因三次打招呼而转人工 |
| 真正缺少型号、用途等必要信息 | 成功发送后才累计；连续两轮仍未明确需求，后续进入人工；空闲满 30 分钟重新计算 |
| 笔身 14cm、笔芯 10cm 被模型对调 | 拦截，不因两个数字都在资料里就放行；同属性的正确单位换算仍可用 |
| 免运费、免邮、包邮等表达 | 核对对应依据、肯定否定、门槛及明确地区例外；正品和相对送达承诺同样检查 |
| 声称退款已完成、订单已取消、地址已改好 | 当前没有执行工具回执，拦截这类已执行说法；退款政策、否定和必要询问保留 |
| 同商品不同问法的明确规格或政策冲突 | 发布前提示；历史版本检索到冲突依据时也不交给模型任选一份回答 |

处理不了的客户话术仍是“不好意思，请稍等”；后台保留具体原因和人工待办，不主动介绍为智能助手。

## 实际验收

先使用愿意配合测试的账号与会话，检查以下情形：

1. 连续发送“你好”“谢谢”“你好”：都能自然接话，后台不应出现“需求仍不明确”。
2. 有两名客户时，让其中一人的问题进入人工：另一人仍能收到回复；核对完后恢复原客户，再发新问题，应继续接待。
3. 如果真实页面已有发送失败气泡：开启后应显示“发送待核对”，不会自动补发。核对后手动完成原问题并恢复客户。无需人为制造网络故障。
4. 在问答实验室中，用自己的已确认资料询问价格、规格、运费和发货时间，检查条件是否保留。不要把本文合成示例当成实际商品资料。
5. 发布遇到冲突时，到“知识缺口与冲突”核对具体条目，修正或撤回错误资料后再检查发布。

日常运行还应查看工作台“接待记录与归档”的运行健康、积压与人工待办。绿色启动提示不代表全天都成功读取和回复了消息。

## 仍然存在的边界

这些是确定性保护与合成场景验证，不是完整语义证明，也不代表真实咨询正确率。规格识别目前只覆盖明确命名的有限属性；复杂条件和表达仍可能需要人工核对。知识冲突检测也不覆盖所有语义矛盾。

本轮没有接入订单或退款执行系统，没有向真实客户发送测试消息，也没有完成真实平台连续数天运行验收。电脑、Edge、登录、本地服务和平台页面仍需保持可用；遇到平台限制沿用停发与人工处理，未增加规避限制的方式。建议继续有人查看待办与运行健康，积累真实脱敏问题后加入业务回归题。
