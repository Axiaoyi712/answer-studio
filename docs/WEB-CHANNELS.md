# 通用网页客服：服务 0.14.0 / 扩展 0.11.0

项目接待入口继续使用网页识别和网页操作。小红书是内置适配器，其他聊天网页通过独立适配文件接入；不同业务共用已审核知识，不共用客户处理状态。

## 升级与开始

1. 暂停正在运行的客服，保存尚未提交的编辑内容。停止旧的 `start.cmd` 服务窗口，再重新运行项目根目录 `start.cmd`。访问 `http://127.0.0.1:3080/api/status`，服务版本应为 `0.14.0`。不要同时启动两份服务占用 3080 端口。
2. Edge 打开 `edge://extensions`，重新加载项目的 `edge-extension` 目录。名称为“知答 · 网页智能客服”，扩展版本 `0.11.0`。
3. 刷新要接待的聊天网页，打开扩展。选择已发布业务和“网页适配”。小红书仍选择内置“小红书”，无需重新填写顾客信息。
4. 新接入的网页先点“仅打开面板，先检测页面”，核对消息归属、账号和当前会话；再验证草稿和单条发送，最后启用日常接待。日常接待继续支持自动打开未读会话、回复、人工接管与恢复。

本轮不会修改正式商品资料、审核状态或已发布版本，已有小红书待办、防重记录和手工草稿沿用原存储键。

## 用本地网页验收完整接待

1. 打开 `http://127.0.0.1:3080/web-chat-demo/chat/a`。这是模拟聊天系统，不连接真实平台。
2. 扩展 →“添加其他聊天网页”→ 下载演示适配文件，再从同一位置导入。文件也在项目 `edge-extension/profiles/web-chat-demo.json`。
3. 选择“通用网页客服演示 · web-demo”和一个已发布业务，先打开面板检测。浏览器若询问当前站点访问权限，允许后继续；不会自动申请访问所有网站。
4. 在页面下方选择客户 A，输入“你好”，点击“模拟客户发送”。确认识别正确后启动日常接待，观察客服回答进入消息区、输入框清空。
5. 切换客户 B，再模拟一条咨询。验证不同客户分别得到回答。再暂停、重新启动，确认旧问题没有重复回复。
6. 手工在客服输入框写一段草稿，给另一位客户发消息，确认草稿保留、其他客户继续接待。
7. 点击“模拟当前页面阻断 / 恢复”。有阻断时，此页面停止发送；解除后重新打开面板启动。其他适配器的运行意图不会被清除。

演示消息和页面数据保存在该浏览器的本地存储。启动自动回复会调用所选业务已配置的模型，按正常用量计费。不要在演示页填写真实个人资料。

## 每个平台分别配置回复要求

工作台 → **03 版本与部署 → 网页渠道回复规则**。

- **渠道 ID**：须与扩展适配 ID 一致，例如 `xiaohongshu`、`web-demo`。输入 `taobao` 只是在保存对应规则，不代表已经完成淘宝页面适配。
- **回复要求**：填写该平台的表达、推广与业务要求。只加入当前渠道的模型上下文，不修改共享商品知识。
- **链接策略**：可选择不发送链接、客户询问时仅提供指定已审核网址，或允许提供本次引用知识中的地址。无依据地址仍不自动发送。
- **联系渠道**：按实际使用场景设置。索取密码、验证码等内容仍由通用发送检查拦截。
- **历史消息时限**：按渠道配置。`0` 表示不按时间过滤，防重仍生效；小红书保留旧配置的 24 小时默认值。

保存渠道规则后，新生成的回答使用新规则。若修改发生在生成和发送之间，旧回答会被拦下重新核对。修改历史消息时限后，应暂停并重新启动相应页面，以重新读取时限。

现有业务规则中如果已经写入某个平台专用要求，应人工移到相应渠道配置，避免继续影响其他渠道。本次没有擅自改写这些已发布业务规则。

## 接入淘宝或其他网页

普通用户日常只选择一次网页适配，不需要填写每个顾客的信息。适配文件由开发者按真实聊天页面配置一次，再导入使用。

通用 DOM 适配要求页面能提供：登录账号的稳定标识、会话和消息的稳定标识、明确的双方消息标记、消息正文、输入框和发送入口。列表的未读属性用于自动打开新咨询。人工窗口使用同站点的会话路径。

参考演示 JSON 修改 `origin`、`pathPrefix`、`conversationPath`、`selectors` 和 `attributes`。规则的含义见 `edge-extension/adapters/dom.js`。同一适配 ID 不允许替换成另一站点或路径，换站点需使用新 ID，以免混用客户状态。

当前可直接使用的是小红书内置适配和本地演示适配。**淘宝、千牛网页版等仍需根据实际页面制作并实测，不能只放开网址后就视作支持。** 当前通用适配处理顶层页面中的 DOM，不包含跨域 iframe、Canvas 聊天、图片 OCR 或远程桌面识别；遇到这些页面需要另写适配器。

小红书既有适配仍依赖其当前页面结构。页面已显示实际访问限制、登录失效或消息归属无法确认时，对应页面停止发送；本轮没有解除平台访问限制，也不会自动绕过验证或限制提示。

## 实现与验证

- `edge-extension/inbox.js`：共用接待调度、生成、发送核对、防重和人工流程。
- `edge-extension/page-adapters.js`：适配选择、来源路径约束、通用输入方法。
- `edge-extension/adapters/xiaohongshu.js`：原小红书读取和页面操作。
- `edge-extension/adapters/dom.js`：可配置 DOM 读取、按钮发送与消息归属核对。
- `channel-settings.mjs`、`records.mjs`：按业务和渠道保存规则，兼容原设置。
- `work/web-channels-browser/result.json`：通用网页接待模拟验收结果。

执行：

```powershell
npm.cmd test
node scripts/verify-inbox-browser.mjs
node scripts/verify-web-channels-browser.mjs
node scripts/verify-workbench-browser.mjs
```

自动测试使用隔离数据库、模拟模型和独立浏览器配置，不向真实顾客发送消息。它验证实现和模拟场景，不证明每个平台的实际网页兼容性或平台授权。

浏览器权限实现参考：[脚本注入](https://developer.chrome.com/docs/extensions/reference/api/scripting)、[可选站点权限](https://developer.chrome.com/docs/extensions/develop/concepts/declare-permissions)。浏览器权限限制到已选站点，程序另外核对来源、端口和聊天路径。
