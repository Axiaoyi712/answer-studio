# 0.13.3：对话衔接与人工服务咨询

服务版本 0.13.3，扩展仍为 0.10.0。本次改进客服回答流程，不修改商品知识、审核结果或发布快照。

## 现在的接待方式

| 场景 | 改进后的处理 |
| --- | --- |
| 客服：“需要介绍P01的规格吗？”；客户：“好” | 结合刚才的提议继续介绍，不能只回“好的，有问题随时问”。“可以”“行”“嗯嗯”“OK”等简短确认也会参考上文。 |
| 客服：“请确认是否需要介绍P01的规格”；客户：“可以” | 即使没有问号，也能继续处理这个确认。 |
| 客户：“好的，谢谢”“谢谢，不用了” | 正常简短收尾，不强行重新询问需求。没有待确认上下文的“好”，也继续使用本地接待。 |
| 客服：“需要帮你退款吗？”；客户：“好” | 交给业务待办流程，对外只回复“不好意思，请稍等”；不假装已经执行退款。确认改地址、取消订单或个人订单查询同样保留业务核实。 |
| 客服：“需要转人工客服吗？”；客户：“可以” | 按客户确认的转接意图进入人工待办。 |
| 客户：“人工客服几点上班？”“有没有人工客服？” | 作为服务信息咨询，按当前业务的有效资料回答，不因为出现“人工客服”就强制转接。 |
| 客户：“你是人工客服吗？” | 如实简短说明是自动回复，不冒充真人，也不直接当成转接请求。 |
| 客户：“人工客服几点上班？现在转人工”或“请提供人工客服” | 明确转接请求优先，进入对应人工待办。 |

上轮的自然收尾、退款规则与实际申请区分、并列退换货政策核对继续保留。各客户的上下文仍然隔离，人工处理仍沿用已有独立窗口和恢复流程。

## 资料依据怎么处理

上文客服提到的商品可以用于查找当前知识，但历史回复本身不能成为价格、规格或承诺的证据。如果历史说了旧价格，仍以当前有效资料为准；当前没有资料时，不能凭历史话术生成可发送的事实回答。

服务时间和人工接待方式同样需要自己的真实资料。没有排班信息时仍等待核实；本次测试使用的九点到六点排班只存在于合成测试文件，没有写入你的知识库。

## 实际验收

1. 刷新本地工作台，确认服务版本为 0.13.3；无需重装扩展。
2. 在问答实验室使用连续对话：先询问某款商品，等回复提出介绍或选择问题，再发送“好”或“可以”。应接着处理上文提议，答案仍依据已发布资料。
3. 在同一对话里发送“好的，谢谢”或“谢谢，不用了”。应正常收尾。
4. 在有真实人工排班资料的业务中，分别测试“人工客服几点上班？”和“人工客服几点上班？现在转人工”。前者回答规则，后者进入待办。
5. 再测试“你是人工客服吗？”。应简短如实说明自动回复。

需要补充服务信息时，到对应业务的“知识与训练”或“对话建库”录入真实安排，审核并发布。不要直接使用测试样例的时段、价格或政策。

## 仍需持续观察

目前使用近期观测到的客服回复判断是否存在待确认问题；复杂反问、很长的混合消息、隐含的办理意图仍可能需要澄清或人工核实。短确认不会授权系统执行退款、修改地址等业务操作。客户真实案例应脱敏后加入该业务回归题，公开数据和合成结果不能代替真实接待质量抽查。
