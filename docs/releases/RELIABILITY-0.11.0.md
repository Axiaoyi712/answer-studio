## 常用操作

**切换历史版本**：进入“03 版本与部署”，在目标版本点击“查看差异并切换”。有回归题时会检查目标快照；核对差异后点“确认切换”。取消不改变版本，也不会新建保护备份。新回复使用目标版本，草稿知识保留。

**创建与校验备份**：进入“06 备份与恢复”，点“立即备份”。创建后校验文件哈希、SQLite完整性和外键关联；可以再次“重新校验”，或下载数据库文件。

**恢复**：保存编辑并暂停全部自动接待，等待建库和问答检查完成。选择备份 → “查看影响并恢复” → 核对全部业务的数据数量与时间 → 输入“恢复全部数据” → 确认。系统先备份当前状态，再以事务恢复；校验失败、数据已变化或中途SQL失败时拒绝覆盖或回滚。成功后工作台刷新，核对业务与有效知识，再主动启动接待。运行状态不从备份恢复为正在运行。

恢复覆盖的是整个数据库里的所有业务，不仅是当前选中的业务。已经发送的聊天消息无法撤回；浏览器登录、待办游标和磁盘归档文件不随数据库倒退。恢复后请核对遗留待办，不能用数据库恢复重复发送历史消息。

## 自动备份范围

- 默认目录为 `data/managed-backups/`。使用隔离 `DB_PATH` 时默认位于该数据库旁边；可通过服务端 `BACKUP_DIR` 指定目录。
- 服务运行期间每6小时创建一次；启动时距上次自动备份已超过6小时则补一份。服务关闭或电脑休眠期间不会执行。
- 自动保留最近14份，只有重新校验通过的旧自动备份才清理。手动备份、恢复前和版本切换前的保护备份不自动删除，升级前放在 `data/backups/` 的文件也不受此策略影响。
- 备份包含知识、业务、历史版本、建库与接待等数据库内容，可能包含客户咨询文字。`.env`、模型密钥、扩展连接令牌、浏览器登录及磁盘归档不包含在数据库备份内，应按实际需要分别保存。
- 每份受管理备份由 `.sqlite` 和同名 `.sqlite.json` 校验文件组成。页面恢复使用受管理目录中的这套文件；跨设备保存时应一起复制整个目录。页面下载的是便于离线保存的独立数据库文件，不自动成为另一设备的受管理备份。
- 恢复要求数据库结构与当前程序匹配。不同结构的旧版升级备份需要使用匹配程序离线恢复，页面会阻止直接覆盖。
- 备份失败在该页面显示原因；不会因此删除当前业务数据。保护备份创建失败时，不执行版本切换或恢复。

## 验收方式

先创建独立测试业务，并用可配合测试的账号验证实际接待，不把测试价格写进正式客服。

1. 依次说“看P01”“不要P02”“刚说那款多少钱”，应继续围绕P01；再说“蓝色也可以”，不能继续保留蓝色排除，也不应自行产生一条库存人工待办。
2. 在隔离故障模拟里让一条模型请求超时，确认其交待办、没有无限重试，另一条咨询随后完成。实际模型断网时所有模型问题都可能受影响，系统不会凭空回答。
3. 创建两个价格不同的测试版本，添加当前回归题。检查不符合要求的旧版本应被阻止；无冲突且检查通过的目标版本可查看差异后确认切换。
4. 对测试数据库备份后添加一个临时业务，再恢复。恢复前预览应看到数量变化，恢复后临时业务消失，保护备份保留。恢复真实业务前必须核对备份时间与覆盖范围。

本轮自动验证包含 `npm.cmd test`、真实Edge隔离页面的接待与工作台操作，以及 `scripts/verify-business-quality-model.mjs` 的4个真实模型合成场景。结果在 `work/reliability/` 汇总，浏览器截图位于 `work/workbench-browser/`。

交付时通过136项测试、56项自动接待浏览器检查、42项工作台浏览器检查和4个真实模型场景；升级后已验证首份自动备份。原有2个业务、130条知识、10个发布版本及建库对话按指纹核对保留，升级备份和回执见 `work/reliability/latest-backup.json`、`deployment.json`、`acceptance.json`。

这些验证不等同真实平台连续一天的试运行，未向真实客户发送测试消息。正式持续接待仍需观察登录、页面变化、漏回复和重复回复情况。
